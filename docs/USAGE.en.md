## Installation

Requirements: Python 3.11 or later, separately installed selected scanners, and Git for direct repository installation. Private repositories require authorized access.

```sh
python -m venv .venv
```

Activate the environment for your operating system:

```sh
# Windows PowerShell
.venv\Scripts\Activate.ps1
# Linux/macOS
source .venv/bin/activate
```

From the root of the distributed source:

```sh
python -m pip install .
ethos-sec --help
```

Alternatively install the supplied `.whl` with `python -m pip install /path/to/ethossecurity-0.1.0-py3-none-any.whl`.

To install the published release from GitHub:

```sh
python -m pip install "git+https://github.com/maiconpl2/ethossecurity.git@v0.1.0"
```

Prefer a reviewed version or commit. Do not put tokens in the URL. Installing EthosSecurity does not install the scanners.

## Prepare your project and run

```sh
ethos-sec init /absolute/path/to/project --adapter openai
ethos-sec scan /path/to/project --profile full-scan --output reports/security.json
```

For `init`, choose `anthropic` or `antigravity` for other clients. The command exports four skills, `ethossecurity.yaml` and an MCP fragment under `.ethossecurity/` without overwriting existing files. Reuse those files for later assessments. Merge the fragment into your client settings and reload it; the command does not automatically register the server.

Available profiles: `bug-hunter`, `app-security`, `infra-security` and `full-scan`. Configuration is read from `ethossecurity.yaml` in the project root when present. To supply trusted configuration explicitly:

```sh
ethos-sec scan /path/to/project --config /trusted/path/ethossecurity.yaml --output reports/security.json
```

## Prepare the tools

The default enables Semgrep, Trivy, Gitleaks and OSV-Scanner. CodeQL and ZAP require preparation and explicit enabling. The profile determines which enabled tools apply.

| Tool | Preparation and scope in this version |
|---|---|
| [Semgrep](https://semgrep.dev/docs/getting-started/) | CLI on PATH; two local starter rules with limited coverage |
| [CodeQL](https://docs.github.com/en/code-security/codeql-cli) | Prepared database and query suite; set `codeql_database`, `codeql_queries` and enable `codeql`. Observe the tool's usage terms |
| [Trivy](https://trivy.dev/) | CLI on PATH; filesystem dependency and configuration scanning. Database downloads may require network access |
| [Gitleaks](https://github.com/gitleaks/gitleaks) | 8.x CLI on PATH; current-file scanning with credential values omitted |
| [OSV-Scanner](https://google.github.io/osv-scanner/) | 2.x CLI on PATH; dependency scanning. Queries may send package metadata |
| [OWASP ZAP](https://www.zaproxy.org/docs/docker/baseline-scan/) | Prepared `zap-baseline.py` runtime; configure `zap_target`, the exact URL in `authorized_targets` and enable `zap` |

Use ZAP only on authorized test targets. Baseline crawls and passively analyzes responses; it does not replace authorization or business-logic tests. The operator must configure the tool, network and crawl scope appropriately.

## Connect your assistant

To run the local server:

```sh
ethos-sec mcp --root /absolute/path/to/project --config /trusted/path/ethossecurity.yaml
```

Configure that command in your client or use the fragment generated by `init`. It points to the Python environment used for installation; preserve that environment.

- **OpenAI/Codex:** merge `.ethossecurity/openai.toml` into the client's MCP configuration.
- **Claude/Anthropic:** merge `.ethossecurity/anthropic.json` into the appropriate MCP configuration. Claude Code uses `.mcp.json`; other clients may use a different location.
- **Antigravity:** merge `.ethossecurity/antigravity.json` into the client's MCP configuration.
- **ChatGPT:** where local STDIO support is available, use the local command. Remote/hosted usage requires a reachable server, authentication and additional setup; no hosted public service is included.

After reloading the client, check `security_profiles` and run `security_scan` with your selected profile. Configurations are prepared; live product connections have not been acceptance-tested.

The `--http` mode listens on localhost and requires a gateway with TLS and authentication for external exposure. Do not expose the server directly. Use operator-controlled configuration.

## Read the results

The JSON includes `executions`, `findings`, `complete`, `policy_failed` and `policy_unknown`. `complete` refers to enabled, applicable tools, not coverage of every security control.

Each finding includes severity, confidence, CWE/OWASP where supplied, file/line or endpoint, evidence, impact, exploitability, recommendation, suggested patch, source and validation status. Undetermined values remain unknown or empty. Alerts start as `unvalidated`; a rule match is not a confirmed vulnerability. Patches are not automatically generated or applied.

| Exit code | Meaning |
|---|---|
| `0` | Requested tools completed and no finding met the configured threshold |
| `1` | Execution completed with findings meeting the threshold |
| `2` | Invalid input, incomplete execution or unknown severity requiring triage |

Unavailable tools, failures and partial assessments are recorded. Confirm context, reproduce risks with test data and validate fixes. No alerts does not prove the absence of problems.

You can also import a supported external report:

```sh
ethos-sec import codeql reports/codeql.sarif --output reports/normalized.json
ethos-sec import trivy reports/image.json --output reports/image-normalized.json
```

## Operation and automation

The included GitHub Actions workflow tests, packages and demonstrates a Semgrep assessment. It has not been executed on GitHub and does not automatically publish packages.

Assess only authorized projects. Process untrusted repositories in isolated environments without production credentials. Review reports before sharing them: paths, endpoints and metadata may also be sensitive.
